# 封控拦截

请求在选槽、出站之前先过一道闸。`/v1` 和 `count_tokens` 共用。拦住就不 hop，不消耗上游额度。管理台入口是「风险审计」（`/cc#/risk`）。

顺序固定，便宜的规则在前，模型在最后，不能调换。

## 五道关

| 顺序 | 关 | 扫什么 | 拦住 |
|------|----|--------|------|
| 1 | 蒸馏 | 收割模板、题目指纹、结构特征 | 默认 403，并封 device |
| 2 | 硬正则 | 用户正文（不含工具回传）上的类别正则 | 403，不进槽；device 封禁开着时并封 device，不进拒答缓存 |
| 3 | 拒答缓存 | 上游拒过的正文、近似正文、已封 device | 400 `policy_blocked`，不可重试且不是登录失效。原文后追加命中原因：设备封禁、完全一致或相似 |
| 4 | 决策模型 | 安全模型逐题打分 | 低于阈值则 403，并封 device，不进拒答缓存。模型不可用且关闭失败放行时只拦本次，不封 device |
| 5 | 放行出站 | 前面都没拦的请求 | 进入槽位 |

「放行出站」不是第六道闸。它同时列出两类没被闸拦住、但结果仍异常的请求：决策模型打分失败后的放行，以及上游自己的拒答。用来看漏拦。

## 账号范围

按平台和套餐收窄关卡覆盖的槽位。风险审计页顶部的「账号范围」可收起，不跟着当前关卡走。

| 选什么 | 匹配 |
|--------|------|
| 平台 · 套餐 | 一对一起算。Claude 是 Max / Pro / 未标注；GPT 用槽位上的套餐，Team 和 Business Premium 都归 Business |
| 指定账号 | 槽位 id、邮箱或名称，一行一个 |

勾选和指定账号取并集。全空 = 所有账号都进关卡。命中范围之外的请求在关卡前放行，日志里记「账号不在范围」。

设了范围之后，GPT 在选中槽位后再判：没有 GPT 套餐、也没有指定账号，就直接放行，不再看「OpenAI 平台」。Claude 默认仍全部进关卡；只有选了 Claude 套餐或指定了账号，才等槽位，没命中的放行。没有范围时，Claude 照旧过闸，GPT 仍看「OpenAI 平台」开关。

范围选空（一个都没命中）等于全部放行，面板会标出来。凭证形式不再作为筛选。

## 蒸馏

总开关、收割包装、普通针、附加正则、题目指纹、返回文案、结构下限和赛题正则都来自风险审计页保存的 `distill-rules.json`。代码不另存一套名单，面板删掉的条目不会补回。

蒸馏检测器保留 system 文本，只取最新一条有正文的 user 消息，并跳过 `tool_result`；历史用户消息不再触发这层的针、指纹和附加正则。后续硬正则仍扫描用户历史正文。内置硬正则不再仅因「知识蒸馏 / 模型蒸馏 / knowledge distillation」等学术用语拦截，仍拦套取思维链等收割表述；面板保存的自定义规则不受此改动删除。

总开关默认开。OpenAI 平台模型整段跳过，不扫针、指纹，也不扫蒸馏类正则。

普通针、题目指纹和结构收割默认再跳过官方 Claude Code 和 0 注入。这是 `skip_official` / `skip_zero`，面板可关。收割包装（`hard_needles`）和附加正则不看这两个跳过。

硬正则里的 distill 类别也不看这两个跳过。关掉硬正则总开关仍然拦这些短语；只有关掉蒸馏总开关才放行。官方客户端和 0 注入仍扫。OpenAI 不扫。

命中返回蒸馏关配置的 HTTP 状态和文案，并封这次请求的 device。出厂值是 403「不允许蒸馏」。

结构收割只在 `max_tokens` 和思考预算都不低于面板上的 `min_max_tokens`，并且正文匹配 `contest_pattern` 时才看。该正则留空则不做这项。单独的思考标签不是蒸馏。

## 硬正则

类别：色情、蒸馏、破解、破限、自定义。蒸馏类见上一节，其余跟硬正则总开关。命中 403，不写入拒答缓存。device 封禁开着时，命中会永久封禁这次请求的 device。

附加正则和内置规则一起扫。`rules: []` 与 `rules: null` 都回落内置规则；关掉这一层用硬正则总开关。扫描前默认去掉常见提醒，并展开正文里的 base64；这两项可关。比较的是用户自己写下的正文，不含 user 轮里的 `tool_result` / `*_tool_result` / `function_call_output`。

## 拒答缓存

只记上游真正拒过的正文。硬正则和决策模型自己打回的拦截不进这张缓存，下次仍重新过闸。

三种命中都是不可自动重试的 400 `policy_blocked`，`code` 仍是 `refusal_guard`，避免 Claude Code 误提示 `/login`。原文后面追加原因，`details.reason` 为：

- `exact`：当前提示词与曾被拒答的内容完全一致
- `similar`：相似，`details.score` 是 0–1 的估计 Jaccard，文案里写成百分比
- `device`：该设备此前已被封禁，`details.ban_reason` 是当时写入的原因（如 `jev:safety`、`hard_regex:jailbreak`）

## 决策模型

最后一道，拆成系统提示和当前指令两阶段；每阶段逐题打分，命中阻断则返回 403。

- 系统提示：收集客户端的 system/instructions 及消息中的 system/developer 文本，按原文 SHA-256 匹配管理员配置的 `trusted_system_hashes`。不匹配时送审，只有完全审核通过的结果进入缓存。缓存按完整审核配置和指纹隔离，进程内最多 512 条、24 小时到期，重启后重新审核。没有内置宽泛的“官方客户端声明即可信”规则。
- 当前指令：取最近一组 user 文本，跳过标准工具结果和配置允许去除的 system-reminder；工具回传后的继续执行仍审核最近的文本指令。Responses 的字符串 input 直接作为指令。user 角色只能说明协议来源，普通文本中的自动消息仍可能被视为指令，不凭内容声明静默跳过。
- 已识别的官方 Claude 自动权限审查：从 transcript 末尾提取当前工具操作，历史 transcript 不再整段送审；系统策略仍独立审核。
- 两阶段长文本都按 `max_state_chars` 分段审核，段间重叠最多 256 字符，不再只审核尾部。分段不能保证所有跨段语义都被模型捕获。
- 当前指令每个新请求都审核，删除旧的正文去重缓存；同一请求在选槽前后重复进入关卡时，仅复用该请求已经通过且正文与配置均未变化的结果。`usage_logs.intercept.audit` 保存系统指纹、来源、字符数、分段数及 `trusted_hash`/`cached_pass`/`judged_pass`/`block`/`error` 状态，不写入审核密钥或完整正文。配置变更会使缓存键变化。

新系统提示第一次可能产生多次分段请求；之后完全相同且审核通过的系统提示不再调用模型。

只有一道题落在阈值下方 0.08 以内时不拦。两道题都低于阈值，或一道题明显更低，仍然拦。只复用系统提示的通过结果，不复用当前指令的结果。

模型不可用时默认放行，风险审计里记为「模型故障放行」。关掉失败放行后，模型不可用则拦本次请求（403，文案写明决策模型不可用），不把 device 写入封禁。真正判违规仍封 device。401 / 429 / 529 会换下一把密钥再试。

没配模型地址时，这道闸等于没接上，不要当成已经在保护账号。

## 日志

每条请求记下过了哪一关、命中词和规则。升级前没有这条记录的旧日志，在风险审计里显示为「未经关卡」。

被放行的正常请求在「日志」，不在拦截流水里。误伤时收紧或关掉对应的关，不要删槽。这一页上未保存的修改，离开时会丢掉。
