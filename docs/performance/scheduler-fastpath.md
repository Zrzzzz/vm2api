# PostgreSQL 调度路径优化

## 修改范围

基于 `86f4411d`（保留 PostgreSQL 定制的 vm2api 1.4.019），分支 `perf/scheduler-fastpath`。
不引入 Redis。并发/RPM/席位仍由单个网关进程管理；本修改不宣称支持多个独立网关对同一账号的分布式并发计数。

- 候选阶段一次 SQL 联合读取账号和运行状态，使用同一 MVCC 快照，不申请账号排他锁。
- 同一次调度的额度、周额度分配、Fable 和临界额度判断复用该快照。检查不会反复创建账号、清理全池或写入账号统计。
- 已持有席位的会话优先只检查所在 VM。禁用、权限变化、凭证/额度不可用时，继续按现有调度规则重新选择。
- 最终占位保留一次账号事务锁，重新读取快照，并复核当前 VM、账号身份、权限、额度、冷却、并发和 RPM。排队票不能直接使用旧候选获得占位。
- 健康探测按 VM 合并并发调用，结果只在明确 TTL 内使用，TTL 从完成时间计算。请求取消不取消其他调用共享的探测；探测失败明确拒绝调度。
- 健康写回由后台完成，仅更新运行状态表，不触碰账号统计和账号锁。旧心跳不能覆盖新心跳，也不能覆盖凭证禁用或模型冷却。
- 后台定期清理过期状态，真正清理时在锁内重新读取，避免覆盖新加的冷却。调度直接比较有效期，不依赖后台清理及时执行。
- 事务失败、探测失败、取消和熔断准入错误不会泄漏本地占位。数据库不可用时明确失败，不使用过期快照放行。

## 计时

`request_attempts.wait_ms` 保留“总调度耗时”口径，新增：

- `queue_wait_ms`：实际队列等待，包括同一设备的调度顺序等待。
- `scheduling_ms`：调度总耗时减去上述排队时间。

两者通过 PostgreSQL 迁移 `004_scheduler_timings.sql` 新增。历史行保留 NULL，不反推排队时间。
日志性能图、详情和供应商链分别展示调度与排队；历史记录显示“调度与排队（未拆分）”。

## 同条件性能验证

2026-10-27，在本机隔离 PostgreSQL 17.6 数据库中使用合成账号和 VM，健康接口为合成实现，不请求模型。
在 Knex 驱动的每条数据库语句前注入 **42ms**，包括 BEGIN、COMMIT 和账号锁查询。
两组使用相同数据、两个候选槽位、已有席位、每轮清空健康缓存；唯一差异是应用实现。

| 实现 | 三次调度耗时 | 每次 SQL（含 BEGIN/COMMIT） | 每次事务/账号锁 |
|---|---|---:|---:|
| 原始 `86f4411d` | 4628.9 / 4699.5 / 4705.2 ms | 105 | 19 / 19 |
| 修改后 | 228.4 / 231.8 / 231.1 ms | 5 | 1 / 1 |

新路径五条语句为：候选快照、BEGIN、账号锁、占位复核快照、COMMIT。
若请求还需读取持久化会话绑定或特定模型策略，会增加相应查询；真实容量排队也不受这个无排队测量上限约束。
这是受控环境的测量，不能代替上线后真实请求的 P95 验收。

## 验证与上线

- `node --test test/postgres/*.test.mjs`：33 项通过，覆盖 PostgreSQL 集成、调度并发、冷却/禁用、取消、锁竞争、健康写回冲突、故障与计时持久化。
- `npm run check`：严格类型、异步类型、Promise lint 和类型回归门禁通过，未放宽基线。
- `npm run test:async-guards`：5 项通过。
- 前端日志显示测试：22 项通过；前端类型检查和构建通过。

运行 PostgreSQL 测试需要提供独立测试库的 PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE/PGSSLMODE。
每个测试创建随机 schema，不对生产数据执行测试。性能回归测试在 `test/postgres/scheduler-fastpath.test.mjs`。

本分支尚未发布到 Volce 或 dev0。发布时应先合入已验证的 1.4.019 版本，备份并恢复验证生产数据；启动会执行新增的第 004 号迁移。迁移只新增可空计时列和非负约束，旧记录保持不变。
